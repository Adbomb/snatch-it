# Шаг 0: пересчёт экономики D56 после D61 — отчёт (2026-11-23)

Задание: DESIGN.md D64, п. 6 — пересчитать модель после D61 («одна покупка Ловибумов — набор из 3 за прежнюю цену»),
цены D56 без владельца не менять, только показать, что изменилось. Модель — `econ84c` (та, по которой утверждена D56),
скрипт — `scripts/sim/economy84/d61_recalc.py`, 200 прогонов на вариант, одинаковые зёрна (повторный запуск даёт те же
числа).

## Коротко

1. **Модель сверена с кодом.** Сила боссов, цены гантелей, уровней музея и Ловибумов, средние доходы существ 4–10 в
   `Config/Progression` и `Config/Catch` совпадают с утверждёнными (`approved.json`). Расхождение одно — D61: модель
   считала, что бросок стоит цену покупки, а в игре покупка даёт 3 штуки (`Catch.PerBuy = 3`).
2. **Модель проверена:** вариант «до D61» повторяет утверждённый отчёт — 14.1 / 28.0 / 56.4 / 84.6 ч против
   14.2 / 28.0 / 56.2 / 84.6.
3. **Как в коде (набор из 3, запас переносится, остаток уровня сгорает при переходе к следующему боссу)** обычный
   игрок приходит к боссам 7 / 8 / 9 / 10 на **12.8 / 26.0 / 53.4 / 80.0 ч** вместо целей 14 / 28 / 56 / 84 —
   на 5–9 % раньше. Опытный — 12.1 / 24.8 / 49.9 / 75.1 ч, неудачливый — 15.2 / 31.0 / 64.5 / 98.1 ч.
4. **Почему так мало:** время держит тренировка (сила — только от гантелей), а Ловибумы — лишь часть трат. При D61 на
   них уходит 4–8 % заработанного вместо 10–24 %; освободившиеся монеты раньше покупают гантели.
5. **Ловибумы по-прежнему ощутимы:** покупка (набор из 3 Бумов) для только дошедшего до босса игрока — около 1 мин
   дохода на боссах 1–3 и 2.6–7 мин на боссах 4–10, у прокачанного — 6 с … 1.8 мин (`scripts/sim/lovibum_prices.py`).
   Средняя успешная поимка подешевела втрое: например, Common босса 5 — около 9.5M → 3.2M.
6. Попутно: `scripts/sim/lovibum_x3_effect.py` (оценка 2026-11-14) больше не запускается — `lovibum_prices.py` при
   импорте перенастраивает вывод; его заменяет `d61_recalc.py` (точнее: набор, а не «цена ÷ 3»).
