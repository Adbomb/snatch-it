# SNATCH IT! (УТАЩИ ЭТО!) — правила разработки

Roblox-игра на Luau. Код в репозитории, в Studio попадает через Rojo.

## Начало сессии
1. Прочитай этот файл и `docs/memory/NEXT_TASK.md`.
2. При необходимости — остальное из `docs/memory/` и нужные разделы `DESIGN.md`.

## Память проекта (`docs/memory/`)
- [ARCHITECTURE.md](docs/memory/ARCHITECTURE.md) — устройство игры: модули, данные, мир.
- [PROGRESS.md](docs/memory/PROGRESS.md) — завершённые задачи (коротко, со ссылкой на коммит).
- [BUGS.md](docs/memory/BUGS.md) — известные ошибки и особенности инструментов.
- [NEXT_TASK.md](docs/memory/NEXT_TASK.md) — текущая задача, следующая и открытые вопросы.

После каждой завершённой задачи обнови нужные файлы памяти в том же коммите.
В память не пиши длинные логи, исходный код целиком и историю переписки — только выводы и факты.

## Источники правды
- `DESIGN.md` — дизайн и решения D1…D29 (зачёркнутые — заменены более поздними). Реализуй только то, что там записано; нет решения — спроси, не придумывай.
- Интерфейс — стандарт **Stud-UI** (D20): Skill `stud-ui-clean-roblox` (загружай только при работе
  над интерфейсом) и модули `src/shared/StudUI/`. Иконку перед использованием проверь в Studio (Success).
  Из `UI_KIT.md` действует только раскладка; цвета редкостей — из Stud-UI (`UITokens.Rarity`).
- Навыки Roblox (`~/.claude/skills`: roblox-data-stores, roblox-security, roblox-networking, roblox-npc-ai,
  roblox-characters-animation, roblox-performance, roblox-studio-mcp, roblox-vfx и др.) — подсказки.
  Если навык советует одно, а DESIGN.md решает другое — прав DESIGN.md; спорное выписать заказчику.
  Текущий интерфейс ещё на UIKit/UITokens — переход после шагов «цвета» и «музеи».

## Порядок работы
- Перед кодом нового шага покажи план файлов и дождись «ок».
- Код только в `src/`. Studio меняй через Rojo; вручную через MCP — только свойства, которые Rojo не умеет
  (и запиши это в BUGS.md / ARCHITECTURE.md).
- Проверка — через Roblox Studio MCP: Play → Output → Stop. Проверки этапа 2 (подбор, выставление,
  хранилище, перестановка, поворот, D10, отказ поддельному uid) должны проходить после любых изменений.
- Снимки — только когда Studio на переднем плане. Чёрный кадр → один раз попроси развернуть Studio.
- Не проси заказчика нажимать что-то в Studio, если можно сделать самому через MCP или файлы.
  Если без него никак — одна короткая инструкция и зачем это нужно.
- Коммит на каждый подпункт, сообщение на русском. Автор: `Claude <noreply@anthropic.com>` через переменные
  `GIT_AUTHOR_*` / `GIT_COMMITTER_*` (git config не трогать). Push в `main` сразу после каждого шага.

## Правила кода
- Сервер решает всё. Клиент только показывает и просит. Каждый обработчик (`Triggered`, RemoteEvent) сам
  проверяет владельца, состояние, расстояние, руки и место; на клиента не полагайся.
- Состояния предметов — только через `ItemRegistry` (граф в DESIGN.md §1). Реестр не пишет в профиль.
  Порядок: все проверки → запись профиля (`DataService`) → переход в реестре; отказ реестра откатывает запись,
  между ними нет `yield`.
- Числа баланса — в `GameConfig`, числа внешнего вида интерфейса — в `UITokens`. Никаких «магических» чисел
  в контроллерах.
- Asset ID не выдумывать. Только переданные заказчиком, загруженные нами или проверенные.
- Модели мира и предметов — в коде (`World/ModelBuilder` + `World/Models/*`), не руками в Studio.
  Всё Plastic (пупырышки даёт MaterialVariant «LegoStuds»), кроме воды, стекла, неона и табличек с текстом.
  Бюджет: карта ≤ 12 000 частей, предмет 8–40, музей ≤ 400.
- Комментарии и тексты игры — на русском. Шапка модуля: что делает и от чего зависит.
- Стиль: StyLua (табы, ширина 120), линтер selene.
