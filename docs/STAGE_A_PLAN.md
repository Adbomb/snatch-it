# Этап А (D74): поимка → «съесть» → прокрутка → капсула — план файлов

На утверждение. Код не начат. От вида этажа этап не зависит: капсула несёт только тему (существо) и редкость этажа.

## Что делает этап
1. Успешная поимка больше не начинает бой. Сервер сразу бросает редкость этажа и выдаёт игроку капсулу в руки.
2. Клиенты показывают катсцену: босс просыпается, отбирает Ловибум, жуёт, отрыгивает капсулу. Видят все рядом.
3. Поймавшему показывается прокрутка ленты редкостей. Результат уже решён сервером, лента — только показ.
4. Капсулу несут в музей по прежним правилам: ночь, кража по дороге, сдача.
5. До этапа В (башня — основной режим) капсула ставится на постамент как экспонат; доход — с множителем редкости.
   Проверки этапа 2 при этом продолжают проходить.

## Порядок на сервере (одним кадром, без yield)
Проверки → бросок редкости → `BossLootService.Award` с редкостью (реестр: AtBoss → Carried, граф §1 не меняется) →
босс занят на время катсцены → события клиентам. Катсцена ничего не решает: выход, гибель или ночь во время неё
обрабатываются как для любой переноски.

## Нужны решения владельца
1. **Сдвиг шансов от редкости существа:** вес каждой следующей ступени × 1 / 1.15 / 1.3 / 1.5 / 1.8
   (Common / Rare / Epic / Legendary / Secret). Предложен в пересчёте экономики, не утверждён.
2. **Удержание по силе** (отношение силы игрока к силе босса):
   - не меньше 1 — обычный шанс Ловибума;
   - меньше 1 — шанс умножается на это отношение, но не ниже 0.05;
   - от 2 и выше — бонус +25 % к шансу, между 1 и 2 растёт плавно.
   Без этого правила после удаления боя любой новичок ловил бы у босса 10.
3. **Капсула до этапа В** ставится на постамент как экспонат — согласны?
4. **Код боя** (`BattleService`, залп дракона, боевой HUD): удалить сразу в этапе А или отключить и удалить отдельным
   шагом после этапа А? Рекомендую отдельным шагом: много тестов завязано на бой.
