## Studio и инструменты
- 2026-11-10 (30 существ босса 3): CFrame хранит float32 — угол «скорость × время сервера» (~1.8·10⁹ с) огрубляется
  до сотен радиан, вращение стоит (пропеллер, лампы, колёса). Большие углы — `% TAU` до CFrame.
- Модель из многих деталей приходит на клиент по частям: суставы, собранные в момент появления корня, неполные
  (у улитки двигались 2 сустава из 4). Дособирать по `DescendantAdded`.
- Без Studio на переднем плане RenderStep не идёт: камера клиента из MCP не двигается, снимки — старые кадры.
- Проверка доставки ногами (босс 3, 2026-11-09): `PathfindingService` в Play отвечает NoPath даже на соседние точки —
  маршрут прокладывать лучами по свободным дорожкам. Середину прохода на границе зон 2 и 3 закрывает сундук
  «Барахолки» (декор, x ≈ −10…10): свободно по x = ±12…18; дальше — x = 14 до z = −92, затем x = 0 до площади.
- DevTools `Exhibit` подряд без паузы: часть отказов «не выставлено: OnMap» — лимит «Поднять»; между командами ≥ 1.2 с.
- Суставы персонажей R15 в Studio (2026-11-07) — AnimationConstraint, а не Motor6D (одно имя: RightElbow и т. п.;
  `workspace.AvatarJointUpgrade` при этом false). Аниматор пересчитывает Transform так, что смещение Attachment0
  гасится, а C0 у них нет: процедурные движения — только поверх Transform в PreSimulation (`client/Util/Joints`).
  Старый замах «Удар» через C0 Motor6D на таких персонажах молча не работал. Из MCP `C0` — только чтение.
- StyLua на весь `ServerTests.luau` и `Config/GameConfig.luau` переформатирует файл целиком (старые расхождения;
  у GameConfig `check_project.py` ищет зоны однострочными — после StyLua «нет зоны 3»): правки в них — без StyLua
  по файлу (проверять `git show HEAD:файл | stylua --check -` до запуска).
- 2026-11-10 (визуальный QA босса 3): Highlight с Adornee = BasePart обводит только эту деталь, без её детей —
  у существ (невидимый корень, блоки внутри) обводки не было. Обводить модель с блоками (см. ARCHITECTURE, обводка).
- Пропавший токен `UITokens` ломает контроллер молча: `cfg.Update == nil` → ошибка сравнения каждый кадр, подписи
  без раскладки (так было после правки ItemLabel). Теперь Lune `check_config` сверяет `x.Имя` клиентских модулей с
  `UITokens` (нашла и старую ошибку: `LovibumRow/LovibumMin` лежали в `UITokens.Museum`, читались из `Inventory`).
- MCP `execute_luau` на клиенте в конце возвращает тот тип камеры, что был в начале вызова (не всегда Custom): после
  своей привязки Scriptable камера так и остаётся Scriptable, и `MuseumCameraController` не работает. Custom ставить
