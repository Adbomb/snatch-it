# Известные ошибки и особенности

## Игра
- В Output при старте: `ContentId: rbxassetid://203785492 failed due to: Asset type does not match` (×3).
  Не из нашего кода (в `src/` этого ID нет) — вероятно, плагин или настройки места. Не мешает.
- Замена Plastic на «LegoStuds» действует на всё Plastic, включая части аватаров игроков (пупырышки на теле).
  Пока считается допустимым для LEGO-стиля.
- Интерфейс пока на UIKit/UITokens; переход на Stud-UI (D20) — шаг 8.
- Stud-UI: 9 собственных текстур набора (`UI.Assets.Studs`, `ShopHeader`, `Basket`, `RobuxCoin`, плашки
  редкостей `UI.Rarities.*.panel`) в нашем месте дают Failure — без них нет пупырышков на кнопках и плашек.
  Из реестра иконок не грузятся 7: Nature/Banana/Banana_1st, Social/Discord/Gamepad_* (5), Social/Twitter/Bird_White.
  Решение D32: плашки и заголовки — Frame + UIGradient + UIStroke, пупырышки — LegoStuds, монета Robux — иконка реестра.

## Перед релизом (загрузить в Roblox / проверить)
- Всё, что подключено через `rbxasset://` (локальные файлы Studio), у игроков не загрузится — заменить загруженными ID.
  Сейчас таких нет: LegoStuds (3 карты), палитра предметов и меш уточки уже загружены (`Config/Textures`, `Config/ItemModels`).
- `GameConfig.DevMode = false`.
- Звуки `GameConfig.Sounds` — ID выбирает дизайнер.

## Studio и инструменты
- MeshPart из `CreateMeshPartAsync(EditableMesh)` не центрирует меш: точка CFrame — начало координат меша
  (у моделей D39 — середина низа), а не центр рамки (проверено лучом 2026-11-01).
- `screen_capture` с позицией камеры иногда отвечает «Request timed out» — повторить тот же вызов. Камера Studio
  широкоугольная (FOV 70): объекты у края кадра крупнее, сравнивать масштаб — на одной глубине и в центре кадра.
- Blender: фаска (`bmesh.ops.bevel`) на невыпуклом вытянутом многоугольнике выворачивает тонкие грани во внутренних
  углах — тёмные полосы в карте нормалей. `art_style.Art.extrude` поэтому без фаски, торцы режутся на выпуклые куски.
- `require` из MCP (Edit и Play) получает отдельную копию модулей, не ту, что у игры, и кэширует её.
  Реальное состояние сервера через неё не видно; для предпросмотра — `World/FreshRequire`.
- `ProximityPrompt:InputHoldBegin()` из MCP после перезапуска Studio перестал срабатывать.
  Нажимать подсказки через MCP `user_keyboard_input` (E/R/F), кнопки окон — через `user_mouse_input`.
- Сервер видит телепорт персонажа с задержкой: после `root.CFrame = …` подождать ~1 с перед действием.
- `screen_capture` даёт чёрный кадр, если Studio не на переднем плане. Выводить вперёд самому: `AppActivate`
  из WScript.Shell возвращает False (Windows не даёт), работает user32 `SetForegroundWindow` с нажатием Alt
  (`keybd_event 0x12`) по `MainWindowHandle` процесса RobloxStudioBeta. Снимки — по одному: пачка из нескольких
  `screen_capture` подряд даёт таймауты и MCP отключается на ~10 с — `list_roblox_studios` и повторить.
- Для снимков в Edit вода (Terrain) и песок не видны: воду строит только Play, песок закрыт Baseplate.
  Временно: Baseplate в ServerStorage, `WorldBuilder.BuildWater()`, после снимков `Terrain:Clear()` и вернуть.
- В клиенте Play `loadstring` недоступен (в Edit — доступен).
- `Lighting.Technology` в этой версии Studio нет (есть `LightingStyle`, `PrioritizeLightingQuality`).
  `MaterialService.PlasticName` скрипты и плагины не пишут — поэтому `LegoMaterial` вызывает
  `SetBaseMaterialOverride` на сервере и клиенте.
- Rojo: изменения `$properties` служб из проекта на лету не применяются; после перезапуска `rojo serve`
  плагин надо переподключить (кнопка Connect в Studio). Вместо этого значения Lighting из проекта можно
  выставить через MCP в Edit (те же числа, что в `default.project.json`) — так сделано 2026-10-29. Rojo 7.7.0 — `~/.aftman/tool-storage/rojo-rbx/rojo/7.7.0/rojo.exe`.
- `WeldConstraint`, созданный до попадания деталей в мир, не тянет приваренную деталь, когда закреплённый
  корень переставляют через CFrame. Для меша предмета используется `Weld` с C0/C1.
- Blender MCP в сессии Claude Code не подключён; Blender 5.2 запускается из командной строки
  (`--background --python`), пути к файлам передавать абсолютные.
- Импорт FBX в Studio через MCP невозможен — только File → Import 3D руками.
- bmesh: после удаления граней новые грани занимают освободившиеся места, а не конец `bm.faces` — «покрасить
  новые грани по индексу» ломается (часть деталей белая). В `lego.py` каждая деталь строится во временном
  bmesh и добавляется в роль через `from_mesh`.
- MaterialVariant на MeshPart ложится не по UV, а своей проекцией с той же плотностью, что на Part
  (проверено EditableMesh-кубами с разными UV). Поэтому модели из Blender — без текстур, только Color + Plastic.
- Поворот в `lego.rot(z=…)`: скат крыши слева (x < 0) поднимается к коньку при z = +угол, справа — при −угол.
- Blender: пути к файлам — абсолютные (`os.path.abspath`), иначе `image.save()` молча не пишет PNG и
  текстура не встраивается в FBX.
- Windows PowerShell 5.1 читает `.ps1` в UTF-8 только с BOM.
- Скриншоты заказчика бывают WebP с расширением `.jpg`: System.Drawing их не открывает («Out of memory»),
  Blender грузит, но `image.save()` пишет «нет данных» — копировать через `pixels` в новый образ и сохранять PNG.
- Превью Eevee рисует обе стороны граней: вывернутые нормали в нём не видны, а Roblox их не рисует. Проверять
  отладочным рендером с `use_backface_culling` (так проверен `Model.voxel_plate`).
- Импорт FBX (Import 3D) поворачивает данные мешей на 180° вокруг вертикали: у детали Orientation 0, центр — в
  (−x, y, −z) от точки привязки. `World/MeshBuilder` ставит деталь в центр из layout и поворачивает на π.
- `World/FreshRequire` даёт каждому модулю свежие копии зависимостей: состояние (например, загруженные меши
  `MeshBuilder`) у копий разное. Поэтому `MeshBuilder.Build` сам вызывает `Preload`. Данные игрока (DataService)
  из MCP тоже не видны — проверки этапа 2 гонять через клиент: клавиши E/R/F, `FireServer`, атрибуты и Output.
- Участки повёрнуты к аллее: сдвиг для телепорта в проверках считать в координатах участка (Floor.CFrame), не
  в мировых — иначе персонаж встаёт между двумя витринами и срабатывает соседняя.
- ProximityPrompt: из нескольких подсказок с одной клавишей Roblox выбирает ближнюю к центру взгляда камеры, а не к
  персонажу. Витрина соседнего ряда за спиной (между персонажем и камерой) перехватывала R/E — радиус подсказок
  витрин уменьшен до 7 (`GameConfig.Museum.DisplayDistance`).
- Персонаж в Studio появляется, пока сервер ещё стартует: долгая загрузка (`MeshBuilder.Preload`) должна идти
  после постройки карты и выключения чужих SpawnLocation, иначе игрок появляется у SpawnLocation шаблона (0, 0, 0).
- `screen_capture` в Play не видит камеру клиента (кадр не меняется) — снимки мира делать в Edit через Preview. (2026-10-31: снимок в Play показал вид клиента вместе с интерфейсом — если кадр не меняется, снимать в Edit.)
- Мерцание карты — z-fighting: две детали разного цвета с гранями в одной плоскости. Когда обе ровно по осям и
  в одной системе координат, кадр стабилен; если модели поставлены разными CFrame (lookAt, нецелые сдвиги),
  под косым углом видны рваные треугольники. Правило: соседние детали — грань детали спереди выступает ≥ 0.1
  или утоплена; совпадающих граней разных деталей не бывает.
- Несколько `screen_capture` подряд: Studio иногда не отвечает (таймаут), MCP пропадает на ~10 с.
- ProximityPrompt показывается, только если её деталь на экране; из нескольких подсказок с одной клавишей
  выбирается ближняя к центру взгляда. В проверках через MCP после телепорта персонажа камера остаётся
  смотреть в прежнюю сторону — ставить камеру клиента на цель (`workspace.CurrentCamera.CFrame = …`) перед
  нажатием. Радиус подсказок витрин 6.5: у канатов до центра витрины ≈ 5, от сундука до витрины 1 — 8.5.
- MaterialVariant, созданные вручную через MCP, дублируются с теми, что создаёт Rojo из проекта; при прототипах
  удалять ручные (в Studio должно быть по одному LegoSquares/Deep/Soft).
- Сканер совпадающих граней округляет плоскости до 0.05: детали с зазором 0.02 считаются совпадающими — и
  правильно, такой зазор издалека тоже мерцает (плитки Банка подняты на 0.12).
- `os.clock()` в Roblox — процессорное время, не настенное: для длительностей с ожиданием брать
  `DateTime.now().UnixTimestampMillis`.
- Тестовые игроки (`Server/Tests/TestPlayer`) — таблицы: их нет в `Players:GetPlayers()`, поэтому циклы по игрокам
  (такт качалки, презентация) их не видят — для тестов есть `Handlers` (например, `GymService.Handlers.TickPlayer`).
  `ItemRegistry` принимает их носителями только в Studio.
- Blender MCP прописан только в Claude Desktop (`%APPDATA%\Claude\claude_desktop_config.json`, `uvx mcp-for-blender`);
  в Claude Code (`~/.claude.json`) его нет. Аддон «MCP for Blender» 1.8 в Blender 5.2 слушает порт 9876, когда
  в Blender нажат запуск сервера; без MCP Blender доступен через этот порт или из командной строки.
- `string.upper` не меняет кириллицу (только ASCII) — заголовки писать сразу нужным регистром.
- Текстура пупырышков набора Stud-UI (140544932962041) месту недоступна (ошибка «not authorized» на клиенте) —
  `StudUI.UI.Assets.Studs` заменена нашей LegoSquares (90809959209755), D32 + D36.
- Ускорение времени в Studio: при ×120 ночь длится 0.25 с, это не больше такта `TimeService` (0.25 с) — для проверки
  ночных правил брать `DevTools.TimeSkip("Night", 2)` без ускорения.
- Blender MCP подключён к Claude Code 2026-10-31 (`claude mcp add blender --scope user -- <uvx.exe> mcp-for-blender`,
  CLI — `~/.local/bin/claude.exe`); инструменты появляются только в новой сессии. В старой сессии тот же сервер
  можно вызвать по stdio (scratchpad `mcp_probe.py`) — проверено: `execute_blender_code` создаёт и удаляет объект.
- `ServerStorage.ImportedModels` Rojo не трогает: уточка удалена оттуда через MCP 2026-10-31 (сохранить место).
- Предпросмотр модели из Blender в Studio без импорта FBX: данные меша → временный модуль в src (Rojo) →
  `AssetService:CreateEditableMesh` + `CreateMeshPartAsync(Content.fromObject(em))` в Edit. Меш НЕ центрируется:
  все детали ставить в одну точку (CFrame начала модели), не в центр габаритов. Модуль и детали — удалить.
- Тело вращения в bmesh: quad `[кольцо k: i, i+1; кольцо k+1: i+1, i]` даёт нормаль к оси — для наружной
  поверхности обход обратный. Eevee рисует обе стороны и прячет ошибку, а Roblox — нет (ножка «полумесяцем»),
  и окклюзия при запекании выходит чёрной. В превью материалов `use_backface_culling = True`.
- SurfaceAppearance (ColorMap/NormalMap/RoughnessMap/MetalnessMap) работает на MeshPart из EditableMesh с UV
  (`AddUV` + `SetFaceUVs`), свойства пишутся из MCP в Edit. HttpService в Edit через MCP недоступен (HttpEnabled
  выключен) — данные мешей только через временный модуль Rojo.
- Rojo «постоянно отключается» (разобрано 2026-11-01), три причины:
  1) `rojo serve` запускался фоновой задачей сессии Claude и умирал вместе с ней (сжатие контекста, конец сессии,
     остановка задачи). Теперь сервер держит `scripts/rojo-serve.ps1` — отдельный процесс (запуск через
     `Invoke-CimMethod Win32_Process Create`, чтобы не зависеть от сессии), перезапускает Rojo через 2 с, журнал
     `%TEMP%\snatch-it-rojo.log`. Из сессии Claude `rojo serve` не запускать.
  2) Rojo 7.7.1 (последний выпуск) падает при удалении ПАПКИ в `src` во время работы: для каждого файла ищет уже
     удалённую родительскую папку (`change_processor.rs:179`, `canonicalize(parent).unwrap()`). Удаление файлов —
     безопасно. Правило: сначала файлы, через ≥ 1 с — пустую папку (проверено). `git checkout`/`stash`, которые
     удаляют папки, тоже роняют сервер — его поднимет `rojo-serve.ps1`.
  3) Плагин сам не переподключается к перезапущенному серверу посреди сессии: `autoReconnect` (выключен по
     умолчанию, включён 2026-11-01 в настройках плагина) работает только при открытии места; в остальное время
     раз в 30 с всплывает «Project 'snatch-it' is serving… Connect» — нажать Connect (через MCP-клик или вручную).
  Плагин в Studio был 7.7.0 при сервере 7.7.1 — `rojo plugin install` поставил 7.7.1 (загрузится после перезапуска
  Studio).
- Превью EditableMesh не переживает перезапуск Studio: меш в месте не сохраняется, MeshPart становится коробкой
  с текстурой-развёрткой («ящики с узором», висят в воздухе на местах деталей). После перезапуска такие превью
  удалить и собрать заново из `<id>.json`.
- После перезапуска ПК сторож `rojo-serve.ps1` не работает — запустить отдельным процессом (`Invoke-CimMethod
  Win32_Process Create`, команда `powershell -NoProfile -ExecutionPolicy Bypass -File scripts
ojo-serve.ps1`).
  Плагин: всплывающее «You synced project 'snatch-it'… Connect» → Connect → окно «Confirm sync» → Accept.
- `execute_luau` из MCP в Server: `require` модулей даёт ОТДЕЛЬНУЮ копию (без участков и игроков) — бой, выход и
  прочее с данными вызывать только через `ServerStorage.DevTools` (BindableFunction), как и тесты.
- Временные показы `workspace.__WondersPreview` / `__BossPreview` в Play — коробки; Main.server удаляет их при старте.
- Только что загруженные картинки (`upload_image`) Roblox обрабатывает ~20–30 с: SurfaceAppearance сначала серый
  («Asset content representation is being generated») — снимки делать после паузы.
- Blender 5.2: запекание цвета для SurfaceAppearance — через EMIT (цвет материала → Emission), а не DIFFUSE: у металла
  диффузный цвет чёрный. Шероховатость и металл — так же, константой в Emission.
