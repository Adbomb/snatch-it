## 2. Автоматическая привязка после ручного импорта

Два новых инструмента:
- **`scripts/studio/collect_boss4_meshes.luau`** — запускается в Studio (Edit) через MCP. Находит MeshPart обоих
  импортов в Workspace, ServerStorage и ReplicatedStorage. Сверяет имена со скелетами в коде. Печатает для каждой
  части: имя, MeshId, размер и метки (свои карты из импорта, повтор имени). Отдельно сообщает, что ещё пришло с
  импортом: кости, анимации, Humanoid.
- **`scripts/boss4_bind_after_import.py`** — проверяет вывод сборщика и вписывает ID. Если есть хоть одна ошибка,
  ничего не пишет.

Что проверяет `boss4_bind_after_import.py`:

| Что | Как |
|---|---|
| Имена MeshPart | 218 видимых частей 30 существ (`Art_<id>_<Часть>`, по `Config/CreatureRigs`, сверено с `Boss4Creatures.index.json`) и 27 частей Сфинкса (`Boss4_Sphinx{Body,Head,Limbs}_<Часть>`; группа в имени = карта части). Нет пропусков и лишних; если имя повторяется (импорт сделан дважды) — предупреждение, берётся первый |
| MeshId | число; не запрещённый ассет (список из `check_project.py`); не ID карты; у разных частей — разные |
| Размеры | общий масштаб импорта (игра ставит размер частей сама) и каждая часть в пределах 3 % от габарита в скелете — иначе меш, скорее всего, от другой части |
| Текстуры | у 30 существ `Config/ItemModels` и `Server/Looks` совпадают с `Boss4_maps.json`; у Сфинкса шаблоны `Looks/Boss4_{Body,Head,Limbs}` совпадают с `BossModels[4].maps`. Свои карты, которые создал импорт, игра не использует — это только сведения |
| Скелеты и анимации | суставы (Motor6D) и клипы собираются кодом (`CreatureRigs`, `Boss4SphinxRig`, `Boss4SphinxClips`). В обоих FBX только меши: 218 + 27, без арматуры, без анимаций, без иерархии (проверено в Blender). Нужно, чтобы у каждой части скелета был меш, — это проверяется |
| После записи | `bind_meshes.py` вписывает `CREATURE_MESHES` (ItemModels) и `SPHINX_MESHES` (BossModels); сверка: вписано всё, прочие блоки (предметы, пёс, торговец, существа босса 3) не изменились; затем `check_project.py` и Lune `check_creatures` |

Проверено:
- **Холостой прогон на габаритах из самих FBX** (`--dry-run`, копии конфигов во временной папке): 245 из 245 имён и
  размеров совпали со скелетами, масштаб ×1.0000. Привязка в копиях: 218 частей существ и 27 частей Сфинкса, прочие
  блоки не тронуты. Файлы проекта не изменились — это сверено по контрольным суммам.
- **Ошибки ловятся** — 9 подстроенных случаев: нет части; размеры двух частей перепутаны; ID карты вместо меша;
  запрещённый ID; пустой MeshId; лишняя часть; один ID у двух частей. Повтор имени и общий масштаб ×0.01 дают
  предупреждение, а не ошибку.
- **Сборщик в Studio:** во время Edit я поставил 245 временных MeshPart с нужными именами и одну кость. Сборщик
  нашёл 245 из 245 и показал «кроме MeshPart в импорте: Bone=1». Заглушки потом удалены.
- **Новый серверный тест** «Босс 4 после импорта: меши 30 существ и 27 частей Сфинкса загружены, с картами». Пока
  мешей нет, он только пишет «ещё не импортированы: 0 из 218, 0 из 27». После привязки он проверит:
  - все части стали мешами (блоков не осталось);
  - на каждом меше есть SurfaceAppearance;
  - у Сфинкса все 27 частей — MeshPart с картами.

## 4. Тесты Сфинкса (отдельные)

| Тест | Что проверяет |
|---|---|
| «Сфинкс занят для второго…» | Пока A ловит существо, пока A дерётся и пока Сфинкс празднует победу и идёт домой, B не может: начать поимку, начать бой, забрать существо. Ловибум у B не списывается, B не попадает ни в поимку, ни в бой, ему сообщают «ловит» / «занят». Когда Сфинкс дома — B ловит, а A теперь не может. «Уйти» без броска не списывает Ловибум |
| «Сфинкс: Ловибум ур. 4 → бой → поражение (отброс) → домой, сон, полное HP → сразу снова → победа → в руках» | Ловибум ур. 3 у Сфинкса не работает. Поражение при силе 0: Сфинкс празднует, игрока отбрасывает (без нокаута), существо на плите, Ловибум не возвращён. Восстановление: Сфинкс дома и спит, цели нет, бой снят, здоровье игрока прежнее. Повтор сразу без паузы: у Сфинкса полное HP. Победа при силе 150 000: существо в руках, слот пуст до рассвета |

Игроки A и B в серверных тестах — NPC-игроки сервера (`TestPlayer`). Это проверка правил сервера, **а не игра двух
настоящих клиентов**.

**Что я исправил по ходу.**
- Первый вариант теста «занят для второго» прерывал бой сразу после начала и ждал этапа возврата. Но такой Сфинкс
  ещё не сходил с места и засыпает сразу — это правильное поведение игры. Тест переделан: этап возврата
  проверяется после победы Сфинкса.
- Форматтер stylua переформатировал весь файл серверных тестов (+6 000 строк). Файл восстановлен: резервная копия до
  правок плюс только новые тесты. После форматирования он совпадает с переформатированным байт в байт, то есть по
  смыслу ничего не потеряно.
- `check_project.py` нашёл в новом скрипте запрещённые ID — они были записаны как список для проверки. Теперь
  скрипт берёт этот список из `check_project.py`, и в файле ID не появляются.

**Не проверено:** настоящие меши (ждут импорта); снимки Studio (`screen_capture` снова ответил тайм-аутом — Studio, видимо, не на переднем плане); два живых клиента; телефон.
